# LINEAGE Deployment

This deploys the LINEAGE FastAPI API on Railway with Postgres, then points the
Vercel-hosted Next.js frontend at that API.

## 1. Database

Create a managed Postgres database in Railway or Neon and copy its connection
string.

```sh
export DATABASE_URL='postgresql://USER:PASSWORD@HOST:PORT/DATABASE'
```

If the provider gives a `postgres://` URL, keep it as-is when setting the env var.
The API normalizes that scheme for SQLAlchemy.

## 2. Signing Key

The API signs manifests with Ed25519. In production the private key must come
from `LINEAGE_ED25519_PRIVATE_KEY_B64URL` and must persist across deploys. If it
changes, previously signed manifests will no longer chain to the same key.

Generate the key locally:

```sh
uv run --project apps/api lineage-generate-signing-key
```

The command prints:

```sh
LINEAGE_ED25519_PRIVATE_KEY_B64URL=...
LINEAGE_ED25519_PUBLIC_KEY_B64URL=...
```

Set only the private key value as a production secret. Do not commit it. Pick a
stable key id and keep it unchanged for the lifetime of that key:

```sh
export LINEAGE_KEY_ID='lineage-production-key-001'
export LINEAGE_ED25519_PRIVATE_KEY_B64URL='PASTE_GENERATED_PRIVATE_KEY'
```

## 3. Backend on Railway

Railway reads `railway.json` from the repo root. It builds the API with
`apps/api/Dockerfile`, runs `alembic upgrade head`, and starts Uvicorn on the
platform-injected `PORT`. The configured health check path is `/healthz`.

Create a Railway project from the GitHub repo and configure the API service:

```sh
Root directory: .
Dockerfile path: apps/api/Dockerfile
Health check path: /healthz
```

Set these service variables in Railway's Variables tab or Raw Editor:

```sh
DATABASE_URL=PASTE_DATABASE_URL
LINEAGE_ENV=production
LINEAGE_CORS_ORIGINS=https://your-vercel-app.vercel.app
LINEAGE_ISSUER_ID=lineage-production
LINEAGE_ISSUER_NAME=LINEAGE Production Issuer
LINEAGE_ISSUER_URL=https://your-public-site.example.com
LINEAGE_KEY_ID=lineage-production-key-001
LINEAGE_ED25519_PRIVATE_KEY_B64URL=PASTE_GENERATED_PRIVATE_KEY
```

Deploy the service, then copy the public API origin Railway assigns:

```sh
export API_URL='https://your-lineage-api.up.railway.app'
curl -fsS "$API_URL/healthz"
```

Expected response:

```json
{"status":"ok","environment":"production"}
```

## 4. Frontend on Vercel

In the Vercel project settings, set:

```sh
NEXT_PUBLIC_API_URL=https://your-lineage-api.up.railway.app
```

Use the API origin only, with no trailing slash. Redeploy the Vercel project after
changing this variable.

## 5. Extension

Build and package the LINEAGE Capture Chrome extension:

```sh
corepack pnpm --filter @lineage/extension build
corepack pnpm --filter @lineage/extension package
```

The unpacked extension is written to:

```sh
apps/extension/dist
```

The uploadable/local distribution archive is written to:

```sh
apps/extension/lineage-capture-extension.zip
```

For local QA, open `chrome://extensions`, enable Developer Mode, choose **Load
unpacked**, and select `apps/extension/dist`. For store distribution, upload
`apps/extension/lineage-capture-extension.zip` through the Chrome Web Store
Developer Dashboard.

After installing the extension, open the LINEAGE Capture Options page and set the
API URL to the deployed API origin:

```sh
https://your-lineage-api.up.railway.app
```

Use the API origin only, with no trailing slash. Set `Project ID` to a real
project, for example `prj_week_zero`, and keep a stable `Operator ID` such as
`op_extension`.

## 6. Verify

Use a real project id and a real event payload for the end-to-end checks:

```sh
export API_URL='https://your-lineage-api.up.railway.app'
export LINEAGE_WEB_URL='https://your-vercel-app.vercel.app'
export LINEAGE_PROJECT_ID='prj_week_zero'
```

Health check:

```sh
curl -fsS "$API_URL/healthz"
```

Create or capture an event, then confirm the ledger can read it:

```sh
curl -fsS "$API_URL/events?project_id=$LINEAGE_PROJECT_ID"
```

Generate and verify a real signed manifest:

```sh
curl -fsS -X POST "$API_URL/manifest/$LINEAGE_PROJECT_ID" > manifest.json
uv run --project apps/api lineage-verify-manifest manifest.json
```

Open the deployed frontend and confirm:

```sh
open "$LINEAGE_WEB_URL"
```

Checklist:

- `/healthz` returns `{"status":"ok","environment":"production"}`.
- The ledger loads events from the deployed API.
- The verifier verifies a real manifest generated by the deployed API.
- `corepack pnpm --filter @lineage/extension build` produces
  `apps/extension/dist/manifest.json`.
- `corepack pnpm --filter @lineage/extension package` produces
  `apps/extension/lineage-capture-extension.zip`.
- A Runway capture from the installed extension appears in the deployed ledger.

## Production Notes

- Never commit `DATABASE_URL`, `LINEAGE_ED25519_PRIVATE_KEY_B64URL`, or production
  origins.
- `LINEAGE_ENV=production` makes the API fail fast if
  `LINEAGE_ED25519_PRIVATE_KEY_B64URL` is missing.
- `LINEAGE_CORS_ORIGINS` is a comma-separated list. Add every deployed frontend
  origin that should call the API, for example:

```sh
LINEAGE_CORS_ORIGINS=https://your-vercel-app.vercel.app,https://www.your-domain.com
```

- Railway config-as-code is intentionally thin here. The Dockerfile is the
  portable deployment contract for Railway, Render, Fly, or any Docker host.
